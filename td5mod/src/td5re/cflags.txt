# Common compile flags — SINGLE SOURCE OF TRUTH, shared by
# build_standalone.bat, td5mod/Makefile, .github/workflows/build.yml and
# release.yml (same pattern as srcs.txt). One flag per line, # comments.
# Path-dependent -I include dirs and variant defines (-DTD5RE_RELEASE
# -DNDEBUG) stay in each build path — everything else lives here.
#
# x86_64 ONLY since the i686 retirement (2026-07-30): the cflags_<arch>.txt
# split collapsed back into this one file. -m64 is pinned explicitly so a
# mis-set toolchain fails loudly instead of silently building the host arch.
# NOT here, and intentionally so:
#   -msse2 / -mfpmath=sse : mandated by the x86_64 ABI, redundant.
#   -DTD5_INFLATE_USE_ZLIB / -DTD5_PNG_USE_ZLIB: the x86_64 toolchain ships no
#       libz.a. td5_inflate.c falls back to its embedded tinfl decompressor
#       (its documented default) and the frame-dump PNG encoder uses its own
#       zlib-free stored-deflate path (output verified against a real decoder
#       2026-07-30). No zlib dependency exists anymore.
# -Wpedantic dropped (2026-07-09, A8 warning paydown): its 33 warnings here
# were all pure ISO-C-strictness noise — 16 "braced-groups within
# expressions" from a GNU statement-expression macro, 17 function-pointer
# <-> object-pointer casts for GetProcAddress-style dynamic loading — not
# real bugs, unlike the four -Werror classes below.
-c
-m64
-O2
-fwrapv
-Wall
-Wextra
-DWIN32
# Hard-error classes (2026-07-06): these indicate real bugs, never style.
# The tree is clean of all four; -Werror keeps it that way.
-Werror=implicit-function-declaration
-Werror=return-type
-Werror=int-conversion
-Werror=incompatible-pointer-types
# x64 memory hunt (2026-07-30): force the raw-CRT allocation logger's macro
# shim into every TU. Resolves via the -I of the td5re source dir that every
# consumer already passes. Inert unless TD5RE_ALLOC_LOG=<MB threshold> is set;
# macros compile out of RELEASE. See td5_alloc_log.h.
-include td5_alloc_log.h
